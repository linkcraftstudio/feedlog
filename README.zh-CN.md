# FeedLog

**开源 AI 客服与用户反馈平台**

AI 驱动的客户支持，通过 Widget、反馈看板和自动迭代的知识库，减少 90% 的人工客服时间，节省团队人力和精力。开源，支持自建部署。

## 痛点

- **客服需求在不知不觉中变多。** 早期由团队亲自回复用户问题，重复咨询持续增加，人力成本与运营负担随之上升。
- **产品知识容易滞后。** 产品更新后，文档和 AI 回答往往无法及时同步。
- **核心团队难以保持专注。** 产品、研发频繁被客服事务打断，拖累产品迭代进度。
- **转人工时，上下文容易丢失。** 用户需要复述问题，处理效率和体验双双下降。
- **用户反馈缺少结构化沉淀。** 需求和 Bug 分散在各类对话中，团队难以梳理规律、确定优先级、评估支持效果。

<img src="https://cdn.feedlog.ai/se/feedlog/oss/readme/pain-points.png" alt="从消息井然到反馈迷失" width="100%" />

## 我们的愿景

**你或许认为暂时不需要客服。但只要创始人、产品或开发人员在回复用户，就已经在承担客服工作。**

FeedLog 无需你搭建昂贵的专职客服团队，也能留住客户支持的价值：AI 根据最新的产品知识应答重复问题，仅在必要时交给人工处理。

每一个 SaaS 团队都应当持续倾听、服务用户，无需在时间和人力成本的压力下，牺牲客户支持的价值。FeedLog 依靠 Widget 和 Inbox 承接咨询，通过反馈看板和路线图打通用户声音与产品规划，再通过更新日志向提需求的用户同步迭代进展，让客户支持持续为你的产品创造价值。

#### 1. 集成 AI 支持、帮助文档与反馈收集的客服组件

一站式承载 AI 答疑与用户反馈，减少大量重复工单，高效捕获产品侧的有效信号。

AI 和人工客服共用一套收件箱，团队统一管理，接手复杂问题时可获取完整的对话上下文，更快完成处理。

让 Agent 基于最新的产品知识和上下文，可靠地回答重复性问题，减少人工客服工作，并从每次对话中持续改进。

对话自动沉淀为可排序的需求，帮团队找准开发重心；用户也能直观看到自己的反馈落地上线。

## 快速开始

只需要三个阶段即可开始使用 FeedLog：

1. 启动 FeedLog。
2. 配置 AI 客服。
3. 将 Widget 接入产品并完成测试。

<img src="https://cdn.feedlog.ai/se/feedlog/oss/readme/quick-start-steps.png" alt="FeedLog 三步快速开始" width="100%" />

如果你不确定选择哪种部署方式，建议先使用 Hosted 云端版。

### 1. 启动 FeedLog

#### Hosted 云端版

这是最简单的开始方式。FeedLog 负责运行服务，你不需要自己准备服务器或数据库。

**[创建 FeedLog 工作区 →](https://auth.feedlog.ai/)**

#### Self-Hosted 自托管

如果你希望在自己的基础设施上运行 FeedLog，可以选择自托管。FeedLog 需要带有 [`vector`](https://github.com/pgvector/pgvector) 扩展的 PostgreSQL 17+ 数据库。

<details open>
<summary><b>部署到云平台</b></summary>

两个平台都会把仓库 fork 到你的账号下，并提示填写必需的环境变量，之后自动完成构建和部署。

| 部署到 Cloudflare Workers | 部署到 Vercel |
| :---: | :---: |
| [![][cf-deploy-img]][cf-deploy-link] | [![][vercel-deploy-img]][vercel-deploy-link] |

详见 [Cloudflare Workers 部署指南](./docs/deploy/cloudflare-workers.md)和 [Vercel 部署指南](./docs/deploy/vercel.md)。

</details>

<details open>
<summary><b>使用 Docker 部署</b></summary>

```bash
git clone https://github.com/linkcraftstudio/feedlog.git
cd feedlog
echo "BETTER_AUTH_SECRET=$(openssl rand -hex 32)" > .env
echo "SYSTEM_ADMIN_EMAILS=you@example.com" >> .env
docker compose up -d
```

启动后，通过 `http://localhost:3000` 访问 FeedLog。详见 [Docker 部署指南](./docs/deploy/docker.md)。

</details>

> [!IMPORTANT]
> 请在创建账号之前设置 `SYSTEM_ADMIN_EMAILS`。列在其中的邮箱注册后会成为工作区所有者；在加入列表之前就已注册的账号，之后不会再被提升。没有所有者，就没有人能管理控制台。全部环境变量见[配置说明](./docs/configuration.md)。

自托管还需要配置模型服务才能使用 AI 功能。具体的部署方式和配置要求，请查看[自托管文档](https://help.feedlog.ai/self-hosting/overview)。

### 2. 配置 AI 客服

#### 添加产品知识

进入 FeedLog 工作区的帮助中心，为以下内容创建文章：

- 常见产品操作流程
- 用户权限和功能限制
- 常见问题和解决方法
- 需要人工支持的情况

为希望 FeedLog Agent 使用的文章打开 **允许 AI 使用**。

建议先从客服团队最常遇到的问题开始，不需要在试用前整理完所有文档。

#### 配置 Agent 行为

启用 Agent 前：

1. 检查反馈看板，区分 Bug、功能需求和产品改进。
2. 打开 **工作区设置 → 反馈组件**。
3. 添加客服邮箱。
4. 设置哪些情况需要向客户提供人工支持指引。
5. 决定客户如何登录：在 **工作区 → 访客权限** 中允许访客访问，或通过 SSO 接入产品已有的用户账号。

FeedLog Agent 和 Widget 使用同一个接入方式，不需要单独安装 Agent。

详见 [Agent 配置文档](https://help.feedlog.ai/agent/setup)。

### 3. 将 Widget 接入产品

安装 Widget：

```bash
npm install @feedlog/widget
```

在应用中初始化：

```ts
import { createWidget } from '@feedlog/widget'

createWidget({
  baseUrl: 'https://your-workspace.feedlog.ai',
  theme: 'auto',
})
```

在 **工作区设置 → 反馈组件** 中复制工作区地址，填写到 `baseUrl`。如果你的产品已有用户账号，请参考 [Widget 与 SSO 接入文档](https://help.feedlog.ai/developers/widget)。

#### 上线前测试

在测试页面打开 Widget，检查以下场景：

- 提出一个帮助中心中已有答案的问题。
- 继续追问一个相关问题。
- 提交一个 Bug 或功能需求。
- 针对账号问题请求人工支持。
- 检查反馈是否被正确保存。

确认一切正常后，再向客户开放 Widget。

## 功能列表

| 功能 | 说明 |
| --- | --- |
| FeedLog Agent | 基于帮助中心回答产品问题，并通过自然对话管理客户反馈。 |
| 产品 Widget | 让客户直接在产品内提问、查看帮助文章和提交反馈。 |
| 帮助中心 | 创建可搜索的分区和文章，并选择 Agent 可以作为产品知识使用的内容。 |
| Inbox | 在一个地方管理 Widget 对话、人工转接和邮件回复通知。 |
| 反馈看板 | 通过帖子、投票、评论和状态流程，统一管理 Bug、功能需求和产品改进。 |
| 相似反馈检测 | 发现相关反馈，在重复需求分散之前将其合并。 |
| 路线图 | 通过公开路线图展示计划中、进行中和已完成的工作。 |
| 更新日志 | 发布产品更新，并根据更新要点和相关反馈用 AI 起草更新说明。 |
| 人工支持指引 | 针对账单、账号、隐私等需要人工处理的问题，配置客服邮箱和处理规则。 |
| 认证与 SSO | 支持邮箱密码、Google、GitHub、访客访问和产品已有账号。 |

## AI 集成

FeedLog 通过 MCP 和 Skills 与 AI 应用和编程 Agent 协作。

- **FeedLog MCP**：将 Claude、ChatGPT、Claude Code、Codex、Cursor 等兼容 MCP 的客户端连接到已授权的 FeedLog 组织，用自然语言查询和管理反馈、看板、重复需求、帮助中心文章和更新日志。
- **FeedLog Skills**：为编程 Agent 提供 FeedLog 的产品知识、接入说明和任务指引。可以用 Skills 接入 Widget 和 SSO、根据代码库起草帮助中心文章，以及处理日常 FeedLog 任务。

在项目中安装 FeedLog Skills：

```bash
npx skills add linkcraftstudio/feedlog-skills
```

MCP 用于访问你的 FeedLog 组织数据；Skills 帮助编程 Agent 理解 FeedLog 并处理你的项目代码。两者可以一起使用，也可以单独使用。

详见 [MCP 与 Skills 指南](https://help.feedlog.ai/mcp)。

### 本地开发

你需要 Node.js、pnpm，以及带有 [`vector`](https://github.com/pgvector/pgvector) 扩展的 PostgreSQL 17+ 数据库。

```bash
git clone https://github.com/linkcraftstudio/feedlog.git
cd feedlog
pnpm install
cp .env.example .env  # 填写 DATABASE_URL、BETTER_AUTH_SECRET、SYSTEM_ADMIN_EMAILS
pnpm migrate          # 初始化数据库结构
pnpm dev              # http://localhost:3000
```

完整的开发环境配置和 Pull Request 流程，请查看 [`CONTRIBUTING.md`](./CONTRIBUTING.md)。
